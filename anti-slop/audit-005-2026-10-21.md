# The Work admin UI audit 005

Date: 2026-10-21
Scope: focused review of the logged-in dashboard, article list, article editor, and related admin forms.

## Findings

### 1. HIGH, C-3 and C-4: The dashboard is global-first instead of role-aware

Evidence:

- `public/app.js:4919-4948` loads every article and renders global totals and recent articles.
- `articleMatchesMe()` exists at `public/app.js:53-57`, but the overview does not use it to show a member's own work.
- `public/index.html:402-416` contains a staff guide, but no visible member-specific dashboard state.

Impact: a staff writer can log in and see newsroom-wide numbers without a clear view of their own submissions, drafts, or published stories.

Smallest useful correction: make the overview adapt to the current role. Staff members should see “My submissions” and personal status counts, while editors and dev users keep newsroom-wide totals. Add a clear empty state when a member has no configured byline names or no matching articles.

### 2. HIGH, R-27 and C-4: Loading, empty, and error states are visually conflated

Evidence:

- `public/app.js:4919-4948` awaits the data request without an admin loading state.
- `Data.listAll()` returns an empty array on failure, so a request error can render as “No articles.”
- `public/app.js:4985-4988` uses one empty message for both no data and no filtered results.

Impact: a failed session or network request can look like a successful empty dashboard, which makes recovery unclear.

Smallest useful correction: add admin skeletons, distinct empty messages, and an error panel with Retry while preserving the current filters.

### 3. HIGH, C-3 and R-31: The article editor is a long undifferentiated form

Evidence:

- `public/index.html:721-855` places thumbnail, metadata, credits, scheduling, excerpt, body, featured status, and save controls in one continuous form.
- The main actions only appear at `public/index.html:850-854`.
- Autosave is represented only by a compact status string at `public/index.html:697-700`.

Impact: writers must scan a large form to find the next task, and the primary save action disappears while editing or reviewing a long story.

Smallest useful correction: group the editor into clear sections such as Basics, Credits, Story, Publishing, and Preview. Add a responsive sticky action bar, a completion summary, and a persistent draft-recovery notice that keeps the existing autosave behavior.

### 4. MEDIUM, R-26 and R-32: Media upload surfaces are discoverable by mouse but not as clear keyboard controls

Evidence:

- `public/index.html:724-733` uses a clickable `div` around a hidden file input.
- `public/app.js:5095-5101` opens the file picker through a click listener rather than a native label or button.
- Paste and drag-and-drop handling exists at `public/app.js:5233-5318`, but the visible UI does not explain those paths consistently or announce their state.

Impact: the editor supports more than the UI communicates, and keyboard and assistive-technology users do not get the same clear upload affordance.

Smallest useful correction: present Upload, Paste, and Drop as explicit actions, use native label/button semantics, add focus states, and announce processing, success, and failure through an aria-live region.

### 5. MEDIUM, C-3: There is no article import flow to improve or discover

Evidence:

- The admin navigation at `public/index.html:371-385` has New Article but no Import Article action.
- The reviewed article form supports image upload and body editing, but no Markdown, plain-text, HTML, or document import parser exists.

Impact: writers who already have a prepared article must paste and format it manually, and the dashboard offers no clear entry point for importing content.

Smallest useful correction: add a deliberate Import Article entry point only after choosing the supported input format. A safe first version would accept Markdown or plain text, show a preview, and require confirmation before populating an active draft.

## Recommended first pass

Implement findings 1 through 4 together as a focused admin UI pass. Treat finding 5 as a separate decision because the supported import format changes the parser, validation, preview, and overwrite behavior.
